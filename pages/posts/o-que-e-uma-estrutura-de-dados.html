Duck To Basics

O que é uma estrutura de dados (e por que você já usa sem saber)

No módulo 1, vimos que algoritmo é uma sequência de passos pra resolver um problema. Mas um algoritmo precisa manipular informação - e essa informação precisa estar organizada de algum jeito dentro do computador.

É aí que entram as estruturas de dados.

O que é uma estrutura de dados?

Estrutura de dados é o jeito como a informação é organizada, armazenada e manipulada na memória do computador. Cada estrutura tem regras próprias de como os dados entram, saem e se relacionam.

A estrutura certa faz seu algoritmo rodar rápido. A errada faz ele travar.

Você já usa estruturas de dados sem saber

Assim como algoritmos, você lida com estruturas de dados no dia a dia:

1. Lista de compras

Uma lista ordenada onde você adiciona itens, risca os que já comprou e percorre do início ao fim. Isso é uma lista/array.

2. Pilha de pratos

Você empilha pratos lavados e tira sempre o de cima. O último que colocou é o primeiro que sai. Isso é uma pilha (stack) - LIFO (Last In, First Out - último a entrar, primeiro a sair).

3. Fila do banco

Quem chega primeiro é atendido primeiro. Isso é uma fila (queue) - FIFO (First In, First Out - primeiro a entrar, primeiro a sair).

4. Agenda de contatos

Você busca "Maria" pelo nome e encontra o telefone dela instantaneamente. Isso é uma tabela hash (hash map).

Classificação das estruturas

As estruturas de dados se dividem em dois grandes grupos:

  • Lineares: os elementos estão em sequência, um após o outro. Ex: arrays, listas ligadas, pilhas, filas.
  • Não lineares: os elementos têm relações mais complexas. Ex: árvores, grafos. (Hash maps são um caso especial - a gente chega lá.)

Neste módulo vamos focar nas estruturas lineares mais importantes, começando pelos arrays.

Estrutura de dados vs Tipo de dado

Não confunda os dois:

  • Tipo de dado: define o que um valor pode ser (int, String, boolean). É uma classificação.
  • Estrutura de dados: define como os valores se organizam (array, pilha, lista). É um container.

Um int é um tipo. Um array de int já é uma estrutura de dados - você tem vários ints organizados em sequência.

Nos próximos posts vamos destrinchar cada uma dessas estruturas - começando pelo array, a mais simples e a base de quase tudo. 🦆

Exercícios

1. Identificando estruturas no dia a dia

Pense em três situações do seu cotidiano que se comportam como: lista, pilha e fila. Descreva cada uma em uma frase.

Mostrar sugestão
  • Lista: playlist de músicas - você adiciona, remove e percorre na ordem que quiser.
  • Pilha: histórico do navegador - o botão "voltar" leva pra página anterior (a última que você visitou).
  • Fila: servidor de impressão - o primeiro documento enviado é o primeiro a ser impresso.

2. Tipo vs Estrutura

Explique com suas palavras: qual a diferença entre um int e um array de int?

Mostrar sugestão

int é um tipo de dado - guarda um único número inteiro. Um array de int é uma estrutura de dados - guarda vários números inteiros organizados em sequência, cada um num índice.

3. (Desafio) Escolha a estrutura

Você precisa implementar o sistema de "voltar" de um navegador. Qual estrutura de dados usaria? E o sistema de "senha de atendimento" de um banco? Justifique.

Mostrar sugestão

Navegador (voltar): pilha (stack). Cada página visitada é empilhada. Ao clicar "voltar", desempilha a página atual e mostra a anterior - LIFO.

Banco (senha): fila (queue). Clientes são atendidos na ordem de chegada - FIFO.

In Module 1, we learned that an algorithm is a sequence of steps to solve a problem. But an algorithm needs to manipulate information - and that information needs to be organized inside the computer.

That's where data structures come in.

What is a data structure?

A data structure is the way information is organized, stored, and manipulated in computer memory. Each structure has its own rules for how data enters, exits, and relates to other data.

The right structure makes your algorithm run fast. The wrong one makes it crash.

You already use data structures without knowing

Just like algorithms, you deal with data structures in everyday life:

1. Shopping list

An ordered list where you add items, cross off what you bought, and go from start to end. That is a list/array.

2. Dish stack

You stack clean dishes and always take from the top. The last one you put is the first one out. That is a stack - LIFO (Last In, First Out).

3. Bank queue

First come, first served. That is a queue - FIFO (First In, First Out).

4. Contact list

You search for "Maria" by name and find her phone number instantly. That is a hash map.

Classifying data structures

Data structures fall into two big groups:

  • Linear: elements are in sequence, one after another. Ex: arrays, linked lists, stacks, queues.
  • Non-linear: elements have more complex relationships. Ex: trees, graphs. (Hash maps are a special case - we will get there.)

In this module we will focus on the most important linear structures, starting with arrays.

Data structure vs Data type

Do not confuse the two:

  • Data type: defines what a value can be (int, String, boolean). It is a classification.
  • Data structure: defines how values are organized (array, stack, list). It is a container.

An int is a type. An array of int is a data structure - you have multiple ints organized in sequence.

In the next posts we will break down each of these structures - starting with the array, the simplest and the foundation of almost everything. 🦆
