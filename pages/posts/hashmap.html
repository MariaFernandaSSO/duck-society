HashMap por dentro: como funciona de verdade

Se existe uma estrutura de dados onipresente no Java, é o HashMap. Você usa todo dia, mas já parou pra pensar no que acontece quando chama put("chave", valor)?

O problema que o HashMap resolve

Com arrays e listas, para encontrar um elemento você precisa percorrer tudo (O(n)) ou saber o índice exato. O HashMap resolve isso com chaves em vez de índices - e encontra qualquer elemento em O(1) na média. 

// Sem HashMap: percorrer a lista pra achar um aluno
for (Aluno a : lista) {
    if (a.getMatricula().equals("2024001")) {
        return a;
    }
}

// Com HashMap: busca direta pela chave
HashMap<String, Aluno> map = new HashMap<>();
map.put("2024001", new Aluno("Maria"));
Aluno a = map.get("2024001"); // O(1) - instantâneo

Como funciona por dentro

1. O hash code

Tudo começa com o método hashCode(). Quando você chama put(chave, valor), o HashMap calcula o hash da chave para decidir onde armazená-la. 

// Passo a passo do put():
// 1. chave.hashCode()  →  um número inteiro (ex: 123456)
// 2. Aplica uma função de dispersão para mapear esse número a um índice do array interno
// 3. Armazena o par (chave, valor) nesse índice

int hash = chave.hashCode();       // ex: 123456
int indice = hash & (tabela.length - 1); // equivalente a hash % tamanho

2. Colisões

Se duas chaves diferentes gerarem o mesmo índice, acontece uma colisão. O HashMap lida com isso usando listas encadeadas (ou árvores quando a lista fica muito grande). 

// Visualmente (simplificado):
// tabela[0] = null
// tabela[1] = ("chaveA", valorA) -> ("chaveX", valorX)  ← colisão!
// tabela[2] = ("chaveB", valorB)
// tabela[3] = null

// Para buscar "chaveX":
// 1. Calcula o hash de "chaveX" → índice 1
// 2. Percorre a lista encadeada no índice 1
// 3. Compara cada chave com equals() até achar "chaveX"

3. Rehash e redimensionamento

Conforme o mapa fica cheio, a performance degrada. Quando o fator de carga (default 0.75) é excedido, o HashMap dobra de tamanho e reorganiza todos os elementos (rehash). É uma operação cara, mas necessária.

Implementação visual

// Se quiséssemos implementar um HashMap simples:
class MeuHashMap<K, V> {
    private static class Entry<K, V> {
        K chave;
        V valor;
        Entry<K, V> proximo;
        Entry(K chave, V valor) {
            this.chave = chave;
            this.valor = valor;
        }
    }

    private Entry<K, V>[] tabela;
    private static final int TAMANHO = 16;

    MeuHashMap() { tabela = new Entry[TAMANHO]; }

    private int indice(K chave) {
        return Math.abs(chave.hashCode()) % TAMANHO;
    }

    void put(K chave, V valor) {
        int i = indice(chave);
        if (tabela[i] == null) {
            tabela[i] = new Entry<>(chave, valor);
        } else {
            Entry<K, V> atual = tabela[i];
            while (atual != null) {
                if (atual.chave.equals(chave)) {
                    atual.valor = valor; // atualiza se já existe
                    return;
                }
                if (atual.proximo == null) break;
                atual = atual.proximo;
            }
            atual.proximo = new Entry<>(chave, valor);
        }
    }

    V get(K chave) {
        int i = indice(chave);
        Entry<K, V> atual = tabela[i];
        while (atual != null) {
            if (atual.chave.equals(chave)) return atual.valor;
            atual = atual.proximo;
        }
        return null;
    }
}

HashMap no Java 8+

Desde o Java 8, quando uma lista encadeada em um bucket ultrapassa 8 elementos, ela é convertida em uma árvore rubro-negra (TreeMap). Isso melhora a busca de O(n) para O(log n) em casos de muitas colisões.

Boas práticas

  • Sempre implemente hashCode() e equals() juntos - contratos do Java.
  • Use chaves imutáveis (String, Integer, etc.). Se a chave muda, o hash muda e o objeto "some" do mapa.
  • Defina a capacidade inicial se souber o tamanho aproximado: new HashMap<>(tamanhoEsperado).
  • Não use HashMap em cenários concorrentes sem sincronização - use ConcurrentHashMap.

If there is one ubiquitous data structure in Java, it is the HashMap. You use it every day, but have you ever stopped to think about what happens when you call put("key", value)?

The problem HashMap solves

With arrays and lists, to find an element you need to traverse everything (O(n)) or know the exact index. HashMap solves this with keys instead of indices - and finds any element in O(1) on average. 

// Without HashMap: traverse the list to find a student
for (Student s : list) {
    if (s.getId().equals("2024001")) {
        return s;
    }
}

// With HashMap: direct lookup by key
HashMap<String, Student> map = new HashMap<>();
map.put("2024001", new Student("Maria"));
Student s = map.get("2024001"); // O(1) - instant

How it works under the hood

1. Hash code

Everything starts with the hashCode() method. When you call put(key, value), HashMap calculates the key's hash to decide where to store it. 

// Step by step of put():
// 1. key.hashCode()  ->  an integer (ex: 123456)
// 2. Applies a dispersion function to map that number to an internal array index
// 3. Stores the (key, value) pair at that index

int hash = key.hashCode();       // ex: 123456
int index = hash & (table.length - 1); // equivalent to hash % size

2. Collisions

If two different keys generate the same index, a collision happens. HashMap handles this with linked lists (or trees when the list gets too long). 

// Visually (simplified):
// table[0] = null
// table[1] = ("keyA", valueA) -> ("keyX", valueX)  <- collision!
// table[2] = ("keyB", valueB)
// table[3] = null

// To find "keyX":
// 1. Calculate hash of "keyX" -> index 1
// 2. Traverse the linked list at index 1
// 3. Compare each key with equals() until finding "keyX"

3. Rehash and resizing

As the map gets full, performance degrades. When the load factor (default 0.75) is exceeded, HashMap doubles in size and reorganizes all elements (rehash). This is an expensive but necessary operation.

Visual implementation

// If we wanted to implement a simple HashMap:
class MyHashMap<K, V> {
    private static class Entry<K, V> {
        K key;
        V value;
        Entry<K, V> next;
        Entry(K key, V value) {
            this.key = key;
            this.value = value;
        }
    }

    private Entry<K, V>[] table;
    private static final int SIZE = 16;

    MyHashMap() { table = new Entry[SIZE]; }

    private int index(K key) {
        return Math.abs(key.hashCode()) % SIZE;
    }

    void put(K key, V value) {
        int i = index(key);
        if (table[i] == null) {
            table[i] = new Entry<>(key, value);
        } else {
            Entry<K, V> current = table[i];
            while (current != null) {
                if (current.key.equals(key)) {
                    current.value = value; // update if exists
                    return;
                }
                if (current.next == null) break;
                current = current.next;
            }
            current.next = new Entry<>(key, value);
        }
    }

    V get(K key) {
        int i = index(key);
        Entry<K, V> current = table[i];
        while (current != null) {
            if (current.key.equals(key)) return current.value;
            current = current.next;
        }
        return null;
    }
}

HashMap in Java 8+

Since Java 8, when a linked list in a bucket exceeds 8 elements, it is converted to a red-black tree (TreeMap). This improves lookup from O(n) to O(log n) in high-collision cases.

Best practices

  • Always implement hashCode() and equals() together - Java contract.
  • Use immutable keys (String, Integer, etc.). If the key changes, the hash changes and the object "disappears" from the map.
  • Set the initial capacity if you know the approximate size: new HashMap<>(expectedSize).
  • Do not use HashMap in concurrent scenarios without synchronization - use ConcurrentHashMap.
