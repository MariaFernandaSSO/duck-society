Duck To Basics

LinkedList: quando faz sentido usar (e quando não faz)

O problema

Imagine que você tem uma lista de convidados para uma festa: 

ArrayList<String> convidados = new ArrayList<>();
convidados.add("Alice");
convidados.add("Bob");
convidados.add("Carlos");
convidados.add("Daniela");

Agora imagine que Bob liga falando que vai levar a namorada, e você precisa inserir "Elena" depois do "Bob". Com ArrayList, você faz: 

convidados.add(2, "Elena");
// Resultado: [Alice, Bob, Elena, Carlos, Daniela]

O que o ArrayList faz por baixo dos panos nessa hora: 

// 1. Array interno: [Alice, Bob, Carlos, Daniela, null]
// 2. Abre espaço no índice 2:
//    [Alice, Bob, null, Carlos, Daniela]
//               ↑ deslocou Carlos e Daniela pra direita
// 3. Insere Elena no índice 2:
//    [Alice, Bob, Elena, Carlos, Daniela]

Esse deslocamento custa caro. Quanto mais elementos, mais lentidão. Se você tiver 10 mil convidados e inserir alguém no começo da lista, todos os 10 mil precisam ser deslocados.

A LinkedList resolve esse problema de um jeito completamente diferente.

Como a LinkedList funciona

Em vez de armazenar os elementos lado a lado num array, a LinkedList cria nós (nodes) espalhados pela memória. Cada nó guarda duas coisas:

  • O valor do elemento
  • Uma seta apontando para o próximo nó da lista
// Visualmente, a lista [Alice, Bob, Carlos] é assim:
//
//  [ Alice | → ]  →  [ Bob | → ]  →  [ Carlos | null ]
//      ↑                ↑                  ↑
//   nó 1             nó 2               nó 3 (fim)
//
// O último nó aponta para null - não tem ninguém depois.

Para inserir "Elena" entre Bob e Carlos: 

// Antes:  [ Alice | → ]  →  [ Bob | → ]  →  [ Carlos | null ]
//
// 1. Cria um novo nó para Elena
// 2. Faz o Bob apontar para Elena
// 3. Faz a Elena apontar para Carlos
//
// Depois: [ Alice | → ]  →  [ Bob | → ]  →  [ Elena | → ]  →  [ Carlos | null ]

Ninguém foi deslocado. Só mudamos duas setas. Não importa se a lista tem 10 ou 10 mil elementos - a operação é igualmente rápida.

O preço que se paga

Se inserir é tão fácil, por que não usamos LinkedList sempre? Porque tem um lado negativo: encontrar um elemento pelo índice é lento.

No ArrayList, lista.get(3) vai direto no índice 3 do array - instantâneo.

Na LinkedList, lista.get(3) precisa percorrer nó por nó a partir do primeiro, contando até chegar no 3: 

// lista.get(3):
// [ Alice | → ]  →  [ Bob | → ]  →  [ Elena | → ]  →  [ Carlos | → ]  →  [ Daniela | null ]
//    ↓ (0)            ↓ (1)             ↓ (2)             ↓ (3) ← achou!
//  começa aqui      conta 1           conta 2          conta 3

Quanto maior a lista, mais passos. Se você fizer get(5000) numa lista de 10 mil, a LinkedList vai percorrer 5 mil nós até chegar lá.

LinkedList vs ArrayList

Operação ArrayList LinkedList
Acessar pelo índice O(1) - acesso direto O(n) - precisa percorrer
Inserir no fim O(1)* - na maioria das vezes O(1) - direto
Inserir no meio O(n) - desloca elementos O(1)** - só reconecta ponteiros
Remover do meio O(n) - desloca elementos O(1)** - só reconecta ponteiros
Memória extra Nenhuma 2 ponteiros por elemento

* O ArrayList ocasionalmente precisa redimensionar o array interno (criar um maior e copiar tudo). Aí fica O(n), mas é raro.
** A LinkedList só consegue inserir no meio em O(1) se você já estiver na posição (ex: usando um Iterator). Se você passar o índice, ela gasta O(n) percorrendo até lá.

Regra de bolso

Pense na sua lista de convidados:

  • Use ArrayList quando: você só adiciona no fim, consulta muito pelo índice, ou percorre a lista do começo ao fim.
    Ex: lista de alunos de uma turma, cardápio do dia, histórico de transações.
  • Use LinkedList quando: você vive inserindo ou removendo no começo/meio da lista, e raramente precisa saber "qual é o elemento na posição X".
    Ex: fila de atendimento, playlist com músicas sendo adicionadas e removidas do meio, histórico de navegação. 
// Exemplo: fila do banco (insere no fim, atende do começo)
// LinkedList é perfeita para isso
Queue<String> fila = new LinkedList<>();

fila.offer("Cliente 1");  // chegou
fila.offer("Cliente 2");  // chegou
fila.offer("Cliente 3");  // chegou

System.out.println(fila.poll()); // atende Cliente 1
System.out.println(fila.poll()); // atende Cliente 2
// Remover do começo é instantâneo na LinkedList

Construindo sua própria LinkedList

A melhor forma de fixar é implementar. Vamos criar uma LinkedList simples, só com encadeamento pra frente e sem usar genéricos para facilitar: 

// 1. O nó: guarda um valor e uma seta pro próximo
class No {
    String valor;
    No proximo;

    No(String valor) {
        this.valor = valor;
        this.proximo = null; // ainda não aponta pra ninguém
    }
}

// 2. A lista encadeada
class ListaConvidados {
    private No primeiro;

    // Adicionar no fim
    void adicionar(String nome) {
        No novo = new No(nome);

        if (primeiro == null) {
            primeiro = novo; // lista vazia, é o primeiro
            return;
        }

        // Percorre até o último nó
        No atual = primeiro;
        while (atual.proximo != null) {
            atual = atual.proximo;
        }
        atual.proximo = novo; // último nó agora aponta pro novo
    }

    // Exibir a lista inteira
    void exibir() {
        No atual = primeiro;
        while (atual != null) {
            System.out.print(atual.valor + " → ");
            atual = atual.proximo;
        }
        System.out.println("null");
    }

    // Buscar um elemento (precisa percorrer)
    boolean contem(String nome) {
        No atual = primeiro;
        while (atual != null) {
            if (atual.valor.equals(nome)) return true;
            atual = atual.proximo;
        }
        return false;
    }
}

// Testando
ListaConvidados lista = new ListaConvidados();
lista.adicionar("Alice");
lista.adicionar("Bob");
lista.adicionar("Carlos");
lista.exibir(); // Alice → Bob → Carlos → null

System.out.println(lista.contem("Bob"));   // true
System.out.println(lista.contem("Zeca"));  // false
Exercícios

1. Remover o primeiro

Adicione um método removerPrimeiro() na classe ListaConvidados que remove e retorna o primeiro elemento. Lembre-se: o segundo elemento vira o novo primeiro.

Mostrar sugestão 
String removerPrimeiro() {
    if (primeiro == null) return null;
    String nome = primeiro.valor;
    primeiro = primeiro.proximo; // o segundo vira o primeiro
    return nome;
}

2. Tamanho dinâmico

Adicione um método tamanho() que percorre a lista e conta quantos elementos existem.

Mostrar sugestão 
int tamanho() {
    int count = 0;
    No atual = primeiro;
    while (atual != null) {
        count++;
        atual = atual.proximo;
    }
    return count;
}

3. (Desafio) Inverter a lista

Implemente um método que inverta a ordem dos nós. O último vira o primeiro e vice-versa, sem usar arrays ou outras listas auxiliares.

Mostrar sugestão 
void inverter() {
    No anterior = null;
    No atual = primeiro;
    while (atual != null) {
        No proximo = atual.proximo; // guarda o próximo
        atual.proximo = anterior;    // inverte a seta
        anterior = atual;            // avança
        atual = proximo;
    }
    primeiro = anterior;
}

LinkedList é uma estrutura simples no conceito, mas poderosa. A diferença é que você precisa entender o trade-off: inserir e remover é barato, mas achar um elemento pelo índice é caro. O ArrayList é o oposto. Saber escolher entre os dois é o que importa.

The problem

Imagine you have a guest list for a party: 

ArrayList<String> guests = new ArrayList<>();
guests.add("Alice");
guests.add("Bob");
guests.add("Carlos");
guests.add("Daniela");

Now imagine Bob calls saying he is bringing his girlfriend, and you need to insert "Elena" after "Bob". With ArrayList, you do: 

guests.add(2, "Elena");
// Result: [Alice, Bob, Elena, Carlos, Daniela]

What ArrayList does under the hood: 

// 1. Internal array: [Alice, Bob, Carlos, Daniela, null]
// 2. Opens space at index 2:
//    [Alice, Bob, null, Carlos, Daniela]
//               ^ shifted Carlos and Daniela to the right
// 3. Inserts Elena at index 2:
//    [Alice, Bob, Elena, Carlos, Daniela]

This shifting is expensive. The more elements, the slower it gets. If you have 10,000 guests and insert someone at the beginning, all 10,000 need to be shifted.

LinkedList solves this problem in a completely different way.

How LinkedList works

Instead of storing elements side by side in an array, LinkedList creates nodes scattered throughout memory. Each node holds two things:

  • The element value
  • A pointer to the next node in the list
// Visually, the list [Alice, Bob, Carlos] looks like:
//
//  [ Alice | -> ]  ->  [ Bob | -> ]  ->  [ Carlos | null ]
//      ^                  ^                    ^
//    node 1            node 2               node 3 (end)
//
// The last node points to null - nothing after it.

To insert "Elena" between Bob and Carlos: 

// Before:  [ Alice | -> ]  ->  [ Bob | -> ]  ->  [ Carlos | null ]
//
// 1. Creates a new node for Elena
// 2. Makes Bob point to Elena
// 3. Makes Elena point to Carlos
//
// After: [ Alice | -> ]  ->  [ Bob | -> ]  ->  [ Elena | -> ]  ->  [ Carlos | null ]

Nothing was shifted. We only changed two pointers. It does not matter if the list has 10 or 10,000 elements - the operation is equally fast.

The price you pay

If inserting is so easy, why not use LinkedList all the time? Because there is a downside: finding an element by index is slow.

With ArrayList, list.get(3) goes directly to index 3 of the array - instant.

With LinkedList, list.get(3) has to traverse node by node from the first one, counting until it reaches index 3: 

// list.get(3):
// [ Alice | -> ]  ->  [ Bob | -> ]  ->  [ Elena | -> ]  ->  [ Carlos | -> ]  ->  [ Daniela | null ]
//    | (0)              | (1)               | (2)               | (3) <- found!
//  starts here        count 1             count 2            count 3

The bigger the list, the more steps. If you call get(5000) on a list of 10,000, LinkedList traverses 5,000 nodes.

LinkedList vs ArrayList

Operation ArrayList LinkedList
Access by index O(1) - direct access O(n) - must traverse
Insert at end O(1)* - most of the time O(1) - direct
Insert in middle O(n) - shifts elements O(1)** - just reconnects pointers
Remove from middle O(n) - shifts elements O(1)** - just reconnects pointers
Extra memory None 2 pointers per element

* ArrayList occasionally needs to resize the internal array (create a bigger one and copy everything). That is O(n), but rare.
** LinkedList can only insert in the middle in O(1) if you are already at the position (e.g., using an Iterator). If you pass an index and make LinkedList traverse there, it costs O(n).

Rule of thumb

Think about your guest list:

  • Use ArrayList when: you only add at the end, access by index often, or traverse the list from start to end.
    Ex: class roster, daily menu, transaction history.
  • Use LinkedList when: you frequently insert or remove at the beginning/middle, and rarely need to know "what is at position X."
    Ex: service queue, playlist with songs being added and removed from the middle, browsing history. 
// Example: bank queue (insert at end, serve from start)
// LinkedList is perfect for this
Queue<String> queue = new LinkedList<>();

queue.offer("Customer 1");  // arrived
queue.offer("Customer 2");  // arrived
queue.offer("Customer 3");  // arrived

System.out.println(queue.poll()); // serve Customer 1
System.out.println(queue.poll()); // serve Customer 2
// Removing from the beginning is instant with LinkedList

Building your own LinkedList

The best way to learn is to implement it. Let us create a simple LinkedList, forward-only and without generics for simplicity: 

// 1. The node: holds a value and a pointer to the next
class Node {
    String value;
    Node next;

    Node(String value) {
        this.value = value;
        this.next = null; // does not point to anything yet
    }
}

// 2. The linked list
class GuestList {
    private Node first;

    // Add at the end
    void add(String name) {
        Node newNode = new Node(name);

        if (first == null) {
            first = newNode; // empty list, this is the first
            return;
        }

        // Traverse to the last node
        Node current = first;
        while (current.next != null) {
            current = current.next;
        }
        current.next = newNode; // last node now points to the new one
    }

    // Display the entire list
    void display() {
        Node current = first;
        while (current != null) {
            System.out.print(current.value + " -> ");
            current = current.next;
        }
        System.out.println("null");
    }

    // Search for an element (must traverse)
    boolean contains(String name) {
        Node current = first;
        while (current != null) {
            if (current.value.equals(name)) return true;
            current = current.next;
        }
        return false;
    }
}

// Testing
GuestList list = new GuestList();
list.add("Alice");
list.add("Bob");
list.add("Carlos");
list.display(); // Alice -> Bob -> Carlos -> null

System.out.println(list.contains("Bob"));   // true
System.out.println(list.contains("Zack"));  // false
Exercises

1. Remove the first

Add a method removeFirst() to the GuestList class that removes and returns the first element. Remember: the second element becomes the new first.

Show solution 
String removeFirst() {
    if (first == null) return null;
    String name = first.value;
    first = first.next; // the second becomes the first
    return name;
}

2. Dynamic size

Add a size() method that traverses the list and counts how many elements exist.

Show solution 
int size() {
    int count = 0;
    Node current = first;
    while (current != null) {
        count++;
        current = current.next;
    }
    return count;
}

3. (Challenge) Reverse the list

Implement a method that reverses the order of nodes. The last becomes the first and vice versa, without using arrays or other auxiliary lists.

Show solution 
void reverse() {
    Node previous = null;
    Node current = first;
    while (current != null) {
        Node next = current.next; // save the next
        current.next = previous;  // reverse the pointer
        previous = current;       // advance
        current = next;
    }
    first = previous;
}

LinkedList is simple in concept but powerful. The key is understanding the trade-off: inserting and removing is cheap, but finding an element by index is expensive. ArrayList is the opposite. Knowing how to choose between them is what matters.
