Big O na prática: como isso afeta seu código

Ao longo deste módulo, vimos várias estruturas de dados e falamos sobre O(1), O(n), O(log n). Mas o que isso significa na prática, no dia a dia?

O que é Big O?

Big O Notation é a forma que usamos para descrever como o tempo de execução (ou uso de memória) de um algoritmo cresce conforme a entrada aumenta.

Não é sobre velocidade absoluta (segundos), mas sobre escalabilidade.

As complexidades mais comuns

Notação Nome Exemplo Crescimento (n=100)
O(1) Constante Acessar array[i], HashMap.get() 1 operação
O(log n) Logarítmica Busca binária, BST balanceada ~7 operações
O(n) Linear Percorrer um array, busca em lista 100 operações
O(n log n) Linearítmica Merge Sort, Quick Sort ~664 operações
O(n²) Quadrática Loop aninhado, Bubble Sort 10.000 operações
O(2ⁿ) Exponencial Fibonacci recursivo ingênuo ~1.27e³⁰ (impossível)

Exemplo prático: busca em listas

// O(n) - Busca em ArrayList (precisa percorrer)
int buscarLinear(List<Integer> lista, int alvo) {
    for (int i = 0; i < lista.size(); i++) {
        if (lista.get(i) == alvo) return i;
    }
    return -1;
}
// Se a lista tem 1.000.000 elementos: até 1.000.000 de passos

// O(1) - Busca em HashMap (direto pela chave)
Map<Integer, Integer> mapa = new HashMap<>();
// ... popular o mapa ...
mapa.get(alvo); // instantâneo, não importa o tamanho

Exemplo prático: loops aninhados

// O(n²) - perigoso com dados grandes!
void bubbleSort(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        for (int j = 0; j < arr.length - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}
// 10 elementos → 100 passos
// 1.000 elementos → 1.000.000 passos
// 100.000 elementos → 10.000.000.000 passos (congela!)

// O(n log n) - muito melhor!
Arrays.sort(arr); // TimSort (Java) = O(n log n)
// 100.000 elementos → ~1.660.000 passos (ok!)

Regras práticas

  1. Remova constantes: O(2n) vira O(n). O que importa é a tendência.
  2. Mantenha o termo dominante: O(n² + n) vira O(n²). O n² domina.
  3. Sempre pense no pior caso: a busca numa LinkedList pode ser O(1) no começo, mas O(n) no pior caso.
  4. Espaço também importa: Big O também vale para memória. Um algoritmo O(n) em espaço dobra a memória com a entrada.

Tabela comparativa das estruturas que vimos

Estrutura Busca Inserção Remoção
Array (ArrayList) O(1) por índice / O(n) por valor O(1)* no fim / O(n) no meio O(n)
LinkedList O(n) O(1)** O(1)**
Stack / Queue - (só topo/início) O(1) O(1)
HashMap O(1)*** O(1)*** O(1)***
BST balanceada O(log n) O(log n) O(log n)
Heap (PriorityQueue) O(1) só na raiz O(log n) O(log n)

* ArrayList: O(1) na inserção no fim na maioria das vezes, mas O(n) quando precisa redimensionar.
** LinkedList O(1) assume que você já está na posição. Chegar lá pode ser O(n).
*** HashMap O(1) é caso médio. No pior caso (muitas colisões) pode ser O(n) ou O(log n) no Java 8+.

Como o Big O impacta seu código real

  • APIs: um endpoint O(n²) pode funcionar com 100 usuários, mas matar o servidor com 10.000.
  • Processamento em lote: processar 1 milhão de registros com O(n log n) leva segundos. Com O(n²), pode levar horas.
  • Mobile: um algoritmo O(2ⁿ) descarrega a bateria em segundos.
  • Bancos de dados: índices existem justamente para transformar buscas O(n) em O(log n).
Exercícios

1. Identificar complexidade

Qual a complexidade do código abaixo? 

for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i * j);
    }
}
Resposta

O(n²) - loop dentro de loop, ambos até n.

2. Otimizar

O código abaixo roda em O(n²). Como otimizá-lo para O(n)? 

boolean temDuplicata(int[] nums) {
    for (int i = 0; i < nums.length; i++) {
        for (int j = i + 1; j < nums.length; j++) {
            if (nums[i] == nums[j]) return true;
        }
    }
    return false;
}
Mostrar sugestão 
boolean temDuplicata(int[] nums) {
    Set<Integer> vistos = new HashSet<>();
    for (int n : nums) {
        if (vistos.contains(n)) return true;
        vistos.add(n);
    }
    return false;
}
// O(n) - percorre uma vez, HashSet é O(1)

3. (Desafio) Três somas

Dado um array, encontre todos os trios (i, j, k) cuja soma seja zero. Tente fazer melhor que O(n³).

A compreensão de Big O é o que separa um código que funciona de um código que funciona bem. Use esse conhecimento para escolher a estrutura certa para cada problema. 🦆

Throughout this module, we have seen various data structures and talked about O(1), O(n), O(log n). But what do these mean in practice, in daily coding?

What is Big O?

Big O Notation is how we describe how the execution time (or memory usage) of an algorithm grows as the input grows.

It is not about absolute speed (seconds), but about scalability.

The most common complexities

Notation Name Example Growth (n=100)
O(1) Constant array access, HashMap.get() 1 operation
O(log n) Logarithmic Binary search, balanced BST ~7 operations
O(n) Linear Traverse an array, search in a list 100 operations
O(n log n) Linearithmic Merge Sort, Quick Sort ~664 operations
O(n²) Quadratic Nested loop, Bubble Sort 10,000 operations
O(2ⁿ) Exponential Naive recursive Fibonacci ~1.27e³⁰ (impossible)

Practical example: searching in lists

// O(n) - Search in ArrayList (must traverse)
int linearSearch(List<Integer> list, int target) {
    for (int i = 0; i < list.size(); i++) {
        if (list.get(i) == target) return i;
    }
    return -1;
}
// If the list has 1,000,000 elements: up to 1,000,000 steps

// O(1) - Search in HashMap (direct by key)
Map<Integer, Integer> map = new HashMap<>();
// ... populate the map ...
map.get(target); // instant, no matter the size

Practical example: nested loops

// O(n²) - dangerous with large data!
void bubbleSort(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        for (int j = 0; j < arr.length - 1; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}
// 10 elements -> 100 steps
// 1,000 elements -> 1,000,000 steps
// 100,000 elements -> 10,000,000,000 steps (freezes!)

// O(n log n) - much better!
Arrays.sort(arr); // TimSort (Java) = O(n log n)
// 100,000 elements -> ~1,660,000 steps (ok!)

Practical rules

  1. Drop constants: O(2n) becomes O(n). What matters is the trend.
  2. Keep the dominant term: O(n² + n) becomes O(n²). The n² dominates.
  3. Always think about the worst case: a search in LinkedList might be O(1) at the start, but O(n) in the worst case.
  4. Space also matters: Big O also applies to memory. An O(n) space algorithm doubles memory with the input.

Comparison table of structures we covered

Structure Search Insertion Removal
Array (ArrayList) O(1) by index / O(n) by value O(1)* at end / O(n) in middle O(n)
LinkedList O(n) O(1)** O(1)**
Stack / Queue - (only top/front) O(1) O(1)
HashMap O(1)*** O(1)*** O(1)***
Balanced BST O(log n) O(log n) O(log n)
Heap (PriorityQueue) O(1) only at root O(log n) O(log n)

* ArrayList: O(1) at the end most of the time, but O(n) when it needs to resize.
** LinkedList O(1) assumes you are already at the position. Getting there can be O(n).
*** HashMap O(1) is average case. In the worst case (many collisions) it can be O(n) or O(log n) in Java 8+.

How Big O affects real code

  • APIs: an O(n²) endpoint might work with 100 users, but kill the server with 10,000.
  • Batch processing: processing 1 million records with O(n log n) takes seconds. With O(n²), it could take hours.
  • Mobile: an O(2ⁿ) algorithm drains the battery in seconds.
  • Databases: indexes exist precisely to turn O(n) searches into O(log n).

1. Identify complexity

What is the complexity of the code below? 

for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {

    }
}
Answer

O(n²) - loop inside loop, both up to n.

2. Optimize

The code below runs in O(n²). How can you optimize it to O(n)? 

boolean hasDuplicate(int[] nums) {
    for (int i = 0; i < nums.length; i++) {
        for (int j = i + 1; j < nums.length; j++) {
            if (nums[i] == nums[j]) return true;
        }
    }
    return false;
}
Show solution 
boolean hasDuplicate(int[] nums) {
    Set<Integer> seen = new HashSet<>();
    for (int n : nums) {
        if (seen.contains(n)) return true;
        seen.add(n);
    }
    return false;
}
// O(n) - traverse once, HashSet is O(1)
